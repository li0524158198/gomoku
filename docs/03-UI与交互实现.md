# 03 · UI 与交互实现

本文档记录 `index.html` 中 UI 层的实现方式：Canvas 渲染管线、动画、音效、
多模式面板状态机与交互守卫。

## 1. Canvas 渲染管线

### 1.1 尺寸与坐标系

```
逻辑尺寸 W = PAD*2 + CELL*(SIZE-1) = 34*2 + 40*14 = 628（正方形）
px(i) = PAD + i * CELL          交点的逻辑坐标
STONE_R = 17.5
```

- 物理画布 = 逻辑尺寸 × devicePixelRatio，`ctx.setTransform(dpr,0,0,dpr,0,0)`，
  逻辑坐标永不关心屏幕密度；resize 时重建。
- **点击映射**：`getBoundingClientRect()` 拿 CSS 实际尺寸，
  `(clientX - left) × (628 / width)` 换算回逻辑坐标（CSS 缩放比任意变化都正确），
  再 `Math.round((mx - PAD) / CELL)` 吸附最近交点。
- 在线自动化测试用同一公式反算屏幕坐标（见 07 文档）。

### 1.2 分层绘制顺序（redraw 每次全量重绘）

```
clearRect → drawWood → drawGrid → 棋子(含动画缩放) → 最后一手标记
→ 胜负高亮 → 提示圈 → 悬停虚影
```

全量重绘在 15×15 规模下毫秒级，换来实现简单（无脏区管理）。

- **drawWood**：三段线性渐变木底色 + 种子随机数生成的 150 颗斑点与 9 条波浪木纹
  （LCG 固定种子，每次重绘纹理一致——随机纹理若不固定，重绘会"闪"）。
- **drawGrid**：网格线、外框加粗、5 个星位、A–O 列标与 15–1 行号。
- **drawStone**：径向渐变（黑子高光偏左上），白子加描边；落子动画期间按
  进度 t 从 1.55 倍缩到 1 倍、阴影渐显。`ghost=true` 时 38% 透明度无阴影。
- **drawLastMarker**：最后一手红点（黑子上红、白子上深红）。
- **drawWin**：先画贯穿五连的半透明金线（lineCap round），再给每颗胜子
  画发光金环（shadowBlur）。
- **drawHint**：金色虚线圆圈（`setLineDash([6,5])` + 发光）。

### 1.3 落子动画

`startAnim(x,y,c)` 把 `{x,y,c,t0}` 压入 `state.anims` 并启动一个 rAF 循环，
循环里过滤超时动画（170ms）、每次重绘；动画队列空了就停表。
重绘时动画中的棋子按 `(now - t0)/160` 插值缩放。在线模式收到服务器广播后
也用 `startAnim` 播放对方落子的下落效果。

### 1.4 悬停虚影（ghost）

`mousemove` 换算最近交点，空点且**当前可落子**才显示（`canGhost` 聚合了
模式、回合、thinking、replay、over 全部条件）；`mouseleave` 清除。
虚影颜色 = 当前行棋方颜色，双人/在线模式下随回合切换。

## 1.5 操作按钮（右侧栏 · 对弈模式之前）

「🔄 重新开始 / ↩ 悔棋 / 💡 提示 / 🔊」位于右侧栏**对局状态卡之后、对弈模式卡之前**
（用户指定的位置），等宽横排；🔊 为固定小宽度的音效开关。

- 二次确认防误触：重开与悔棋是破坏性操作，第一次点击进入**红色确认态**
  （文案变「确认重开？/ 确认悔棋？/ 请求悔棋？」），3 秒内再次点击才执行，
  超时自动还原；同一时间只允许一个按钮处于确认态（armConfirm/disarm 辅助函数）；
- 在线模式的悔棋确认后发送的是**悔棋请求**（对方仍可拒绝），同样走二次确认；
- updatePanel 发现按钮被禁用而处于确认态时立即还原（如进入回放/他人回合）；
- 提示与音效为无害操作，不拦截；确认态文案较长会临时压缩同行按钮宽度，
  属预期表现（确认态 3 秒即还原）。
## 2. 音效（WebAudio 合成）

无任何音频文件：`sfx(kind)` 用振荡器 + 增益包络即时合成。

- `place`：620Hz 三角波短音 + 210Hz 正弦底（"嗒"）。
- `win`：523/659/784/1047 四连琶音；`lose`：330/262/196 下行三音；`draw`：440Hz 单音。
- AudioContext 懒创建（首次用户手势后），挂起时 resume；整体 try/catch，
  合成失败静默（不影响对局）。
- `state.muted` 开关由 🔊/🔇 按钮控制。

## 3. 多模式面板状态机

### 3.1 模式类

`body.mode-ai / mode-pvp / mode-online` 三选一，CSS 控制：

```css
body.mode-pvp .ai-only, body.mode-online .ai-only { display: none; }  /* AI难度、先手选择 */
body.mode-ai .online-only, body.mode-pvp .online-only { display: none; } /* 在线对战卡 */
```

切换模式 = 换 class + `newGame()`（在线模式先行 `netLeave()`）。
分段控件的高亮、模式说明文案统一由 `applyModeUi()` 管理（切换与**恢复存档**共用，
见 05 文档）。

### 3.2 updatePanel：每个模式一个分支

`updatePanel()` 是面板的唯一写入点（status / lastInfo / 双方名牌 / 四个按钮的可用态），
内部按状态分流，**先到先得、后互不干扰**：

1. `state.replay` → 回放分支：状态栏"▶ 回放中 · 第 i/n 手"，名牌按被回放记录的
   模式显示（人机：你/AI；双人：黑方/白方；在线：你/对方），重开/悔棋/提示全禁用。
2. `mode === "online"` → 在线分支：未连接 / 等待对手 / 观战中 / 轮到你 / 等待对方
   各有文案；观战者重开/悔棋/提示全禁用并显示「加入对局」按钮（有空位时）；
   名牌 = 你(执X) VS 对方(执Y)。
3. 其余 = 本地分支：人机（你 执X VS AI 执Y）与双人（黑方 先行 VS 白方 后行）。

### 3.3 结算浮层 overlay

胜/平后显示：标题（🏆 你赢了 / 🤖 AI 获胜 / 🏆 黑棋获胜 / ⚪ 白棋获胜 / 🤝 平局）、
五连坐标串、手数；按钮「再来一局」（`restartGame`，在线模式转发服务器）与
「悔棋复盘」（本地模式隐藏浮层并 `undoMove`；在线模式只关浮层——悔棋走协商流程）。
观战者的终局浮层没有「再来一局」。

浮层刻意放在棋盘**底部**且遮罩很淡（rgba .30 + blur 1.2px）：
第一版的居中重遮罩把获胜连线完全盖住（R1 踩坑，见 06 文档）。

## 4. 交互守卫清单（谁在什么时候能落子）

`humanMove(x, y)` 的守卫链（自上而下）：

| 守卫 | 原因 |
|------|------|
| `state.replay` | 回放中棋盘只读 |
| `hint = null` | 任何落子（无论是否成功）都使旧提示失效 |
| online：未连接 / 观战者 / 未轮到 / 对局已结束 / 点位非空 | 以服务器为准，本地只上报 |
| ai：未轮到玩家 | AI 回合 |
| `state.over \|\| state.thinking` | 终局与思考锁 |
| 目标点非空 | 占用 |

失败路径全部静默返回（不弹错误），用户从状态栏了解原因。
悬停虚影 `canGhost` 与提示按钮 `btnHint.disabled` 用**同一套条件的镜像**，
保证"看起来能下"和"实际能下"永远一致。

## 5. 对局流程

```js
humanMove → (online? netMove : doPlace → finishCheck → scheduleAi)
scheduleAi → thinking=true → setTimeout(160ms) → chooseAiMove → doPlace → finishCheck
```

- `scheduleAi` 的 160ms 延迟让「AI 思考中…」先渲染出来（AI 计算是同步阻塞的，
  最长 12 秒——必须先画界面再算）。
- **令牌防串局**：`state.token++` 后闭包捕获，重开/退出后旧定时器回来自动作废。
- `finishCheck`：查 winLine → 设 winner/winCells/over → 浮层 + 音效 + `saveRecord`
  + `saveLive`；满盘 → 平局分支。
- `undoMove`：人机撤 2 手（末手是 AI 则先撤 AI 再撤玩家）、双人撤 1 手；
  清 over/winner/winCells 并 `saveLive`。在线模式不走这里（走悔棋协商）。

## 6. 移动端与自适应

- `@media (max-width: 1000px)`：面板移到棋盘下方、宽度取 `min(628px, 100vw - 48px)`。
- Canvas CSS 宽度同步缩放，点击映射按实际 rect 换算，触屏无需额外处理
  （click 事件在移动端可用）。
- 页面整体 `flex + wrap`，窄屏自动纵向排列。
