# 01 · 项目总览

## 1. 项目是什么

一个**单文件、零依赖**的网页五子棋，支持：

- 人机对弈（七档 AI 难度，最强档 12 层迭代加深搜索）
- 同屏双人对战
- 在线远程对战（房间号匹配 + 观战 + 断线重连）
- 对局记录与自动回放、落子提示、悔棋、音效、**退出后自动续上**

`index.html` 双击即可离线玩单机模式；在线模式需要另起一个零依赖的 Node 服务器
（`node gomoku-server.js`，默认 3000 端口；
或用 Docker/启动脚本一键部署，详见 docs/08）。

## 2. 文件与职责

| 文件 | 行数级 | 职责 |
|------|--------|------|
| `index.html` | ~1900 | 全部客户端：引擎（纯逻辑）、Canvas 渲染、音效、对局流程、记录/回放、在线客户端、持久化 |
| `gomoku-server.js` | ~230 | 在线服务器：房间匹配、SSE 推送、行棋中继、**权威胜负判定**、观战、闲置清理 |
| `test-engine.mjs` | ~150 | 引擎单元测试：从 index.html 提取引擎代码块在 Node 中运行，80+ 断言 |
| `docs/` | — | 本文档目录 |

`index.html` 内部按区块组织（均有注释分隔线）：

```
/*__ENGINE_START__*/ … 引擎：纯逻辑，不依赖 DOM … /*__ENGINE_END__*/
  ├─ 常量（SIZE / SC 棋型分值表 / WIN_SCORE / nodeCap）
  ├─ Game 类（棋盘、place/undo、makesFive、winLine）
  ├─ pointScore（单点棋型评估）
  ├─ evaluate / genCandidates / findWinPoints / hotFive
  ├─ negamax（α-β + 迭代加深 + 杀棋延伸）
  └─ chooseAiMove（AI 主入口：战术优先 → 分档搜索）
UI 层
  ├─ Canvas 绘制（木纹 / 网格 / 棋子 / 胜负高亮 / 提示圈）
  ├─ 音效（WebAudio 合成，无外部资源）
  ├─ 对局流程（humanMove / scheduleAi / finishCheck / newGame / undoMove）
  ├─ 提示（showHint / drawHint）
  ├─ 记录与回放（saveRecord / startReplay / setReplayIdx …）
  ├─ 在线客户端（netJoin / handleNetMsg / applyNetState …）
  ├─ 自动续上（saveLive / tryResume / applyModeUi）
  └─ 面板与事件绑定
```

**引擎与 UI 之间的边界是刻意的**：引擎块不引用任何 DOM/浏览器 API，
`test-engine.mjs` 与 `gomoku-server.js` 都用同一套正则把这块代码抽出来在 Node 里跑——
一份逻辑，三处复用（页面 / 测试 / 服务器），保证"单机 AI、测试断言、服务器判定"三者行为完全一致。

## 3. 三种模式的会话模型

| 模式 | 状态权威方 | 恢复方式 |
|------|-----------|----------|
| 人机对弈 | 本地 `state.game` | localStorage 快照（`gomoku_live_v1`），轮到 AI 自动续下 |
| 双人对战 | 本地 `state.game` | 同上 |
| 在线对战 | **服务器** `room.game` | localStorage 保存会话（房间号+令牌+角色），重开页面自动重连，以服务器 `init` 广播重建棋盘 |

## 4. 核心技术决策（为什么这么做）

1. **单文件交付**：用户双击即玩，无构建、无依赖、无网络请求（单机模式）。
   代价是 index.html 较长，用清晰的区块注释弥补。
2. **棋型评估用"5 格滑窗"而不是经典枚举棋型表**：
   一条规则同时覆盖连三/跳三/连四/跳四等所有形态（详见 02 文档 §4），
   代码量小且不易漏。代价是评估粒度粗于顶级引擎，够用到人机对弈场景。
3. **在线模式服务器权威**：客户端只上报"想落子"，合法性校验与胜负判定全在服务器
   （复用同一引擎），两端状态不可能不一致。这是"准确判断胜负"需求在网络化后的自然延伸。
4. **SSE + POST 而非 WebSocket**：回合制游戏对延迟不敏感；SSE 让服务器保持
   零依赖（Node 内置 http 即可，不需要手写 WebSocket 帧协议），浏览器端
   EventSource 自带断线重连。详见 04 文档 §2。
5. **测试与服务器共享引擎提取机制**：`/*__ENGINE_START__*/` 标记正则提取，
   引擎改动即被三处同时感知，杜绝"页面修了、服务器判定没修"的漂移。
6. **localStorage 自动续上 + sessionStorage 标签页指纹**：
   刷新/关页重开自动恢复是高频需求；用 sessionStorage 指纹防止同浏览器多标签页
   抢占同一场在线对局。详见 05 文档 §4。

## 5. 功能全景（当前状态）

- 15×15 棋盘，无禁手，五连/长连即胜，满盘平局
- 七档 AI：入门（贪心+随机）/ 进阶（2 层）/ 大师（4 层+延伸）/ 宗师（6 层迭代加深）
  / 棋圣（8 层，5 秒）/ 棋仙（10 层，8 秒）/ 棋神（12 层，12 秒）
- 精确战术层：任何档位都会一步成五、挡对方成五（不会漏杀漏防）
- 提示（💡 按钮 / H 键）：按大师级引擎为当前行棋方计算推荐点
- 悔棋：人机模式撤双方各一手；双人模式撤最后一手；在线模式需对方同意
- 对局记录：自动存档（最近 50 局）+ 自动回放（播放/单步/拖动/变速）
- 在线：房间号匹配、可选房间密码、观战（≤5000 人）、空位递补、断线 8 秒宽限、多窗口接管通知
- 自动续上：本地局面 + 在线会话均实时持久化
- 音效（可静音）、最后一手标记、AI 思考用时显示、移动端自适应

## 6. 快速上手

```bash
# 单机：直接双击 index.html

# 在线对战：
node gomoku-server.js          # 默认 3000 端口
# 两位玩家浏览器打开 http://<IP>:3000 → 「在线对战」→ 输入相同房间号

# 引擎回归测试（约 40 秒，含高难度对弈压测）：
node test-engine.mjs
```
