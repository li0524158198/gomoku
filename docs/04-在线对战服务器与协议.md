# 04 · 在线对战服务器与协议

本文档描述 `gomoku-server.js` 的架构、消息协议、房间生命周期与权限模型。

## 0. 启动与端口

```bash
node gomoku-server.js 3000          # 单端口
node gomoku-server.js 3000-3010     # 端口范围：被占用自动顺延
PORT_RANGE=3000-3010 node gomoku-server.js
HOST=0.0.0.0                        # 监听网卡（默认全部，云部署用）
```

- 启动成功会**自动打开默认浏览器**（`GOMOKU_NO_OPEN=1` 禁用，容器/云服务器建议设置），
  并打印本机与局域网访问地址。
- 端口全部不可用时优雅退出并打开首选项地址（可能服务器已在运行）。
- 配置来源：本机 `config.json`（git 忽略，模板为 `config.example.json`，首次启动自动生成）→
  内置默认。可配置端口/监听地址/观战上限/房间回收时间/重连宽限/密码长度；详见 08 文档 §2.5。
## 1. 总体架构

```
玩家A浏览器 ──POST /api/room/:id/join──▶ ┌─────────────┐
玩家A浏览器 ◀──SSE /events（事件流）──── │ gomoku-server │
玩家B浏览器 ◀──SSE /events（事件流）──── │  rooms: Map   │
观战者C    ◀──SSE /events（事件流）──── └─────────────┘
           ──POST /move、/action（上报）──▶        ▲
                                          权威 Game 实例（从 index.html 提取）
```

- **SSE（Server-Sent Events）负责下行推送，POST 负责上行上报**。
- 选型理由：回合制棋类对延迟不敏感；SSE 让服务器只用 Node 内置 `http` 模块
  （WebSocket 需要手写帧协议或引依赖），浏览器 EventSource 自带断线重连。
  一个页面仅占用 1 条长连接，远低于 HTTP/1.1 每域名 6 连接限制。
- **服务器是唯一权威**：落子合法性、回合顺序、胜负判定全部在服务器完成
  （Game 类从 index.html 的引擎标记提取，与页面/测试共用一份逻辑）。
  客户端收到广播后整体重建棋盘（applyNetState），两端状态不可能漂移。

## 2. 房间模型

```js
room = {
  id,                                   // 规范化房间号（大写字母数字，≤8 位）
  players: { [BLACK]: seat|null, [WHITE]: seat|null },
  spectators: Map<token, {res}>,        // 观战席（≤10 人）
  game: Game,                           // 权威棋局
  pendingUndo: color|null,              // 待处理的悔棋请求
  ts,                                   // 最近活跃时间（TTL 用）
}
seat = { token, res, detachTimer }
```

- `hasSeat(r, c)` = 座位存在**且 token 非空**——token 是座位占用的唯一凭证
  （ detach 只清 token，座位对象保留以便宽限期重连判断；判断逻辑必须用
  hasSeat 而不是对象真值，这是踩过的坑，见 06 文档 R5）。
- 令牌：`crypto.randomBytes(9).toString("hex")`，join 时签发。
- 房间号规范化：trim → 大写 → 去除非字母数字 → 截断 8 位。

## 3. HTTP 接口

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/`、`/index.html` | 返回游戏页面（Cache-Control: no-store，保证改版即生效） |
| POST | `/api/room/:id/join` | 加入 `{pwd?}`：空位即入（先黑后白），满员转观战；房间有密码时 `pwd` 必须匹配（玩家与观战一致）；返回 `{token, color, roomId, specCount, state}` |
| GET | `/api/room/:id/events?token=` | SSE 事件流（玩家与观战者共用，attach 后下发 init） |
| POST | `/api/room/:id/move` | 落子 `{token, x, y}`：校验终局/双方在场/回合/点位 → place → 判胜 → 广播 |
| POST | `/api/room/:id/action` | `{token, type}`：`restart` / `undoRequest` / `undoResponse{accept}` / `takeSeat` / `leave` |
| GET | `/api/room/:id/peek?token=` | 校验令牌是否仍有效（玩家与观战者均支持；客户端重连自检用） |

- 所有 API 带 CORS 头（`*`），OPTIONS 204 预检——支持 file:// 打开的页面连服务器。
- 请求体 JSON，>100KB 直接断开。
- 广播 `broadcast(r, type, extra)`：组装一次 JSON，依次写给两个座位 + 全部观战者，
  写失败 try/catch 静默（死连接由 close 事件清理）。

## 4. 事件协议（SSE 下行，`data: {type, state, ...}`）

每条事件都携带**全量房间状态** `state = {moves, winner, draw, winCells, turn, seats, specCount}`，
客户端以此为唯一事实整体重建，不做增量补丁——协议简单且自愈。

| type | 时机 | 客户端行为 |
|------|------|-----------|
| `init` | SSE attach 后私发（含 `you`: 座位色或 0） | 设置 myColor/role，重建棋盘 |
| `join` | 有人 attach（玩家入场/重连） | 更新 seats/oppJoined，重建 |
| `leave` | 玩家断线超宽限或主动离开 | 更新 seats，重建，隐藏悔棋协商条 |
| `move` | 服务器接受一手落子 | 重建 + 落子音效；若终局 → 存档 + 战报浮层 |
| `restart` | 任一玩家重开 | 清存档标记，重建空盘 |
| `undoRequest` | 悔棋请求 | 请求方提示等待；对方弹出同意/拒绝条 |
| `undo` | 对方同意 | 重建（服务器已撤一手并清胜负） |
| `undoDeclined` | 对方拒绝 | 提示"对方拒绝了悔棋请求" |
| `spec` | 观战人数变化 | 刷新提示文案 |
| `replaced` | 同一座位被另一窗口接管 | 旧窗口本地退出，提示让位 |

### 权限矩阵

| 操作 | 黑座 | 白座 | 观战者 |
|------|------|------|--------|
| 落子 | 本回合 ✓ | 本回合 ✓ | 403 |
| restart / undoRequest / undoResponse | ✓ | ✓ | 403 |
| takeSeat | 400（已在对局） | 同 | 有空位时 ✓ |
| leave | ✓ | ✓ | ✓ |

## 5. 连接生命周期（断线重连语义）

```
attach:  清除旧 detachTimer（若有）→ 通知旧连接 replaced → p.res = 新 res → 下发 init → 广播 join
         （同一座位重复 attach = 另一窗口接管，旧窗口收到 replaced 后自行退出）
detach:  res 'close'（连接真断）→ res=null → 启动 8 秒宽限 detachTimer
         宽限期内同 token 重新 attach → 清除 timer，座位无感保留
         超时仍无连接 → 清 token → 广播 leave → 座位可被重新加入
```

- **8 秒宽限（RECONNECT_GRACE）**：网络抖动/手机锁屏不掉座位，对手无感。
- **res.on("close") 而不是 req.on("close")**：现代 Node 中 GET 请求体读完即触发
  req 的 close（请求完成语义），会误杀刚建立的 SSE——这是实测踩出的坑（06 文档 R5）。
- 玩家永久离开：对手收到 `leave`，房间保留棋盘与空位，房号重进即可续战。

## 6. 观战与空位递补

- join 时对局席满员 → 分配观战令牌（`color: 0`，SPEC_MAX = 5000）。
- 观战者与玩家收同一份广播，`stateOf` 附带 `specCount` 供界面显示。
- 观战者无落子/重开/悔棋权（服务器 403），离开即释放名额。
- `takeSeat`：对局席出现空位时，观战者可转正——从 spectators 删除、占座、
  广播 join；客户端随后**关闭并重建 SSE**（以玩家身份重新 attach，拿到新 init）。

## 6.5 房间密码

- 首位加入者提交的密码（trim 后 ≤16 字符，**区分大小写**）即房间密码；
  房间不存在时按该密码创建——后加入者无法更改。
- 房间已设密码时，**一切加入（对局席与观战席）** 都必须携带相同密码，
  否则 403「房间密码错误」；密码错误不消耗任何名额。
- 座位空出后房间密码继续有效（重进需凭密码）；房间删除时密码随之消失。
- 撤销防护：peek / takeSeat / move 等基于令牌的操作不重复验密码——
  令牌本身就是通过密码后才签发的。
- 客户端把密码随 live 存档保存（本机），刷新续上时自动回填并锁定输入框；
  非属主窗口接管存档时同样回填，便于手动重进。
- 定位：这是"熟人房间口令"而非安全认证——明文存储与传输（无 TLS），
  用途是防止陌生人误入，不防有心人。

## 7. 房间回收

每 60 秒巡检：双侧无座且无观战者超过 60 秒，或任何房间闲置超 2 小时（ROOM_TTL）→ 删除。
内存占用有界；服务器重启即全部失效（客户端通过 peek 404 自动感知并提示重新加入）。

## 8. 客户端在线模块要点

- `NET_BASE`：页面由 http(s) 提供时用同源；file:// 打开时回退 `http://127.0.0.1:3000`。
- `handleNetMsg`：每条消息先更新 seats/specCount/oppJoined，再按 type 分支，
  分支末统一 `refreshOnlineHint(); updatePanel(); redraw();`——不遗漏任何一处 UI。
- `applyNetState(st, animateLast)`：整体重建（reset → 按序 place → 回填胜负），
  只在新棋子到达时播放落子动画与音效；重建本身与渲染解耦。
- `checkNetEnd`：终局时区分玩家（存档 + 「你赢了/对方获胜」）与观战者
  （仅战报浮层，不存档）。
- 重连自检：SSE onerror → 3 秒后 `peek`；403/404（房间已失效）→ 本地清理 +
  提示重新加入；网络不可达 → 继续等待 EventSource 自动重连。
