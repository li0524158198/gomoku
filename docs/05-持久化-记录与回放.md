# 05 · 持久化：对局记录、回放与自动续上

本文档描述三块持久化机制：对局记录（records）、退出自动续上（live）、
以及建立在记录之上的回放引擎。

## 1. 对局记录（gomoku_records_v1）

### 1.1 存储结构

```js
state.records = [{                     // 新记录 unshift 到头部，保留最近 50 条
  ts: Date.now(),
  mode: "ai" | "pvp" | "online",
  level: 1..7,                         // 人机模式有效
  humanColor: BLACK|WHITE,             // "你"的执色（在线 = 存档方视角）
  result: "win" | "lose" | "black" | "white" | "draw",
  moves: [[x, y, c], ...],             // 完整落子序列 —— 回放的全部依据
}]
```

持久化到 `localStorage["gomoku_records_v1"]`，读写均 try/catch（隐私模式降级为内存态）。

### 1.2 写入时机与去重

- `saveRecord()` 在**对局终局**时调用：`finishCheck`（本地胜/平）、`checkNetEnd`（在线胜/平）。
- `state.recSaved` 标志保证一局只存一次；newGame / undo / restart 时复位。
- **内容去重**：写前比对新记录与现有第一条的 `moves` 签名，完全相同则跳过。
  原因：同一浏览器开两个标签页对战时，两端都会收到终局广播、各存一条——
  去重后只留一条（真实双设备各自独立存储，不受影响）。
- 在线模式**观战者不存档**（不是自己的对局，没有"你"的视角）。

### 1.3 展示口径

`recResultText`：人机 → "🏆 你获胜 / 🤖 AI 获胜"；双人 → "⚫ 黑方胜 / ⚪ 白方胜"；
在线 → "🏆 你获胜 / 😔 对方获胜"；平局 → "🤝 平局"。
`recMetaText`：`MM-DD HH:mm · 模式 · N 手`（模式含难度名：人机·大师 / 双人 / 在线）。

## 2. 自动回放引擎

### 2.1 数据与状态

回放不生成新数据，只是把 `records[i].moves` 逐步重放到棋盘上：

```js
state.replay = { rec, idx: 0..n, playing, speed, timer }
state.snapshot = snapGame()   // 进入回放前的完整对局快照（退出时恢复）
```

### 2.2 核心循环 setReplayIdx(i)

**从空盘重放前 i 手**（不是增量推进）：

```js
g.reset();
for (k = 0; k < i; k++) g.place(...rec.moves[k]);
if (i === n) { 重算终局：winLine 末手 → winner/winCells；满盘 → draw；state.over = true }
```

- 选择"重放式"而非"增量推进/回退"：`g.undo()` 只弹一手，回退多手需要循环；
  重放式幂等、无状态漂移，且天然支持进度条任意跳转（拖到第 17 手就是重放 17 手）。
  单步成本 = 重放 i 手 ≈ 微秒级，无性能问题。
- 回放到终局时重算胜负与 winCells → 金色连线自然重现；单步回退则清空胜负状态。
- 播放器：`toggleAutoPlay` 用 setInterval 按 SPEEDS（×1=700ms / ×2=350ms / ×4=150ms）
  推进；到终局自动停；播完再按 ▶ 从头重播。变速立即生效（stopAutoPlay + toggleAutoPlay）。
- 键盘：←/→ 单步、空格播放暂停（仅回放模式激活时拦截，preventDefault 防止页面滚动）。

### 2.3 快照与恢复（进得去、出得来）

- 进入回放：`snapGame()` 深拷贝当前对局（moves / winner / draw / winCells / over / recSaved）。
- 退出回放：`restoreSnapshot()` 按快照重建——正在下到一半的对局、甚至已结束带
  五连高亮的终局，都原样回来。
- 若进入回放前没有对局（首次加载即点回放），快照为 null → 退出时 `newGame()`。
- 回放期间：落子/悔棋/重开/提示全部被守卫拦截；`stopReplayOnly()`（重开等操作用，
  不恢复快照）与 `exitReplay()`（恢复快照）分离。

### 2.4 清空记录

两段式确认：第一次点「清空」变「确认清空？」（2.5 秒后自动还原），再点才真清。
防手滑，无需确认弹窗。

## 3. 退出自动续上（gomoku_live_v1）

### 3.1 live 快照结构

```js
{
  ts, mode, level, humanColor,
  moves: [[x,y,c]...], winner, draw, over, winCells, recSaved,
  tabKey,                                    // 标签页指纹（sessionStorage）
  online: { roomId, token, role, myColor } | null
}
```

**写入点**（状态一变即存，全量覆盖）：
`doPlace`（任何人落子）、`applyNetState`（在线每次广播后）、`undoMove`、`newGame`、
难度切换、`netJoin/netLeave/netTakeSeat`（会话变化）、`finishCheck`（终局补存）。

### 3.2 恢复 tryResume()

```
读 live → 无则正常空启动
已结束的本地局 → clearLive，全新开始（终局结果在记录里可回放）
恢复 mode/level/humanColor → applyModeUi 同步分段控件与 body class
按 bounds/非空校验重放 moves → 回填胜负
【自洽校验】重算末手 winLine：旧存档若漏记胜负在此修复（终局补存前的历史遗留）
online 会话：
  tabKey 匹配（本标签页刷新/重开同标签）→ 恢复会话 → connectEvents() → init 以服务器为准重建
  tabKey 不匹配（别的窗口的会话）→ 不抢占；预填房间号，本窗口接管存档
人机模式且轮到 AI → scheduleAi() 自动续下
```

### 3.3 在线会话续上的三层保障

1. **页面刷新**：sessionStorage 指纹保留 → 会话恢复 → 服务器宽限期内重连不掉座位。
2. **关闭后重开（新标签）**：指纹已失 → 不自动续上，但房间号预填；8 秒宽限后
   旧座位自动释放，点「加入」即回到对局（棋盘仍在服务器，2 小时 TTL）。
3. **服务器重启**：peek 404 → 自动清理会话并提示重新加入。

### 3.4 多标签页防护（tabKey 指纹）

同一浏览器的多个标签页**共享** localStorage——没有指纹时，B 标签页加载会读到
A 标签页的在线会话并以 A 的令牌连接，服务器把流切给 B，A 收到 `replaced`
被挤下线，且两边的存档互相覆盖形成竞争。

指纹方案：saveLive 记录写入者的 sessionStorage 指纹；tryResume 只在指纹匹配
（= 同一标签页刷新）时恢复在线会话，不匹配则不抢占、预填房间号并把存档接管权
交给当前窗口。已知边界：同浏览器多标签同时下不同的棋仍会互相覆盖存档
（后写者胜），见 07 文档。

### 3.5 服务器侧配合

- SSE `replaced` 事件：同一座位第二次 attach 时，向旧连接发 replaced 并 end——
  旧窗口据此本地退出（不开新对局、不破坏对方状态）。
- **删除了 beforeunload 自动退房**：它会先于恢复流程清掉会话存档，
  让"刷新续上"变成"刷新即退房"。真正的离开由 SSE 断开 + 8 秒宽限处理，
  玩家主动退房仍走「退出房间」按钮（显式 netLeave）。

## 4. 键与生命周期小结

| 键 | 内容 | 写入时机 | 清除时机 |
|----|------|----------|----------|
| `gomoku_records_v1` | 最近 50 局 | 每局终局 | 「清空」两段确认 |
| `gomoku_live_v1` | 当前对局快照 | 每次状态变更 | 仅当"已结束的本地局"被读到时 |
| `sessionStorage.gmk_tab` | 标签页指纹 | 首次写入 | 关闭标签页（浏览器行为） |
