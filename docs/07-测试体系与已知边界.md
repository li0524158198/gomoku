# 07 · 测试体系与已知边界

## 1. 测试矩阵总览

| 层 | 手段 | 频率 |
|----|------|------|
| 引擎逻辑 | `test-engine.mjs`（Node 单元测试） | 引擎每次改动后 |
| 页面脚本 | 提取 `<script>` 后 `node --check` | 每次编辑后 |
| 服务器脚本 | `node --check gomoku-server.js` | 每次编辑后 |
| 服务器 API | Node 脚本直连 REST/SSE 冒烟 | 协议改动后 |
| 浏览器 E2E | 浏览器自动化（多标签页模拟多玩家） | 每轮功能完成后 |
| 人工体验 | 真人下棋 | 随时 |

## 2. 引擎单元测试（test-engine.mjs）

### 2.1 提取机制

引擎块以 `/*__ENGINE_START__*/` / `/*__ENGINE_END__*/` 标记围合，测试脚本：

```js
const m = html.match(/\/\*__ENGINE_START__\*\/([\s\S]*?)\/\*__ENGINE_END__\*\//);
const api = new Function(m[1] + "\n;return {Game, pointScore, chooseAiMove, ...};")();
```

服务器 `gomoku-server.js` 用完全相同的提取——**一份引擎代码，页面/测试/服务器三处一致**。

### 2.2 断言分组

1. **胜负判定**：横/竖/两条对角线五连、断开三连不误判、六子长连（返回全部棋子）、
   winLine 坐标单调性、虚拟成五判定（该成/不该成）。
2. **棋型评估**：活四 ≥100 万、补成五 =1000 万、一端被堵成冲四（非活四）、
   跳四填隙成五、散子组合分不虚高。
3. **AI 战术**（各档位抽样）：
   - 直接成五取胜（含跳四填隙，黑/白双方、多档位）；
   - 堵对方唯一成五点；
   - 封堵对方活三两端之一（宗师档额外接受"冲四反先"的更强应对）；
   - 自己能成五时优先于堵对方；
   - 开局阶段贴棋筋落子。
4. **性能与稳定性**：AI 对弈压测——大师 30 手、宗师 10 手、棋圣 5 手、棋仙 4 手、
   棋神 3 手，逐手断言落点为空点 + 单手耗时上限（13 秒 = 棋神 12 秒上限 + 余量）。

### 2.3 mkGame 辅助与回合不变量

`mkGame(blacks, whites)` 按黑先交替的顺序摆子——`moves.length` 奇偶决定行棋方，
测试构造局面时必须保证"黑白数量关系"与"想测的行棋方"一致。
多轮测试失败都源于此处（详见 06 文档），现已形成固定检查项。

## 3. 服务器 API 冒烟（Node 脚本）

不依赖浏览器，直接 fetch 验证协议：

- join × 2 → 第三人 409（满员，R6 后转观战 color:0）；
- SSE 用 `fetch` reader 逐块解析 `data:` 行，收集事件序列；
- 九手脚本对局 → `move` 广播携带 winner=1 与 5 格 winCells；
- 终局后落子 400、非己回合 400、非法坐标 400、观战者落子/重开 403；
- undoRequest → undoResponse(accept) → undo 事件携带"清空胜负后的 8 手"；
- restart 广播空盘；leave 后座位释放（重新 join 拿到空出的颜色）；
- takeSeat：观战者接管空位并正常落子。

## 4. 浏览器 E2E 场景库（历史用例汇总）

自动化通过浏览器控制完成，固定流程：**新开独立标签页 → 操作 → 断言 → 关闭**
（共享标签页会被真人操作污染，见 06 文档附录）。

| 场景 | 验证点 |
|------|--------|
| 点击落子 | 真实坐标点击 → 本地棋子 + AI 应答 + 状态/名牌更新 |
| 人机胜负 | 构造四连 → 点击成五 → 浮层/五连坐标/记录存档/棋盘锁定 |
| AI 胜负 | AI 四连续杀 → 「对方获胜」视角战报 |
| 双人模式 | 交替落子、悔棋一手、胜负战报、模式往返切换 |
| 记录回放 | 自动存档、自动播放到终局、单步/回开头、退出恢复原局面、双人记录口径、两段式清空 |
| 提示 | 按钮与 H 键、采纳即失效、终局/回放/他人回合禁用、双人双方可提示 |
| 在线对局 | 双标签匹配、真实点击同步、脚本对局至五连、双端战报各自视角、悔棋同意/拒绝、重开、退出 |
| 观战 | 第三标签满员进入、实时同步、操作禁用矩阵、空位出现「加入对局」、接管后落子 |
| 自动续上 | 本地刷新恢复（含 AI 回合自动续下）、结束局清空、脏存档自愈、在线刷新续战、非属主窗口不抢占 |

坐标点击公式（与页面映射互逆）：
`screenX = rect.left + (PAD + x*CELL) × (rect.width / 628)`。

## 5. 性能预算（实测基线）

| 项 | 预算 | 实测 |
|----|------|------|
| 大师（4 层）单手 | < 2.5 秒 | 通常 10-100ms，最慢 ~110ms |
| 宗师（6 层）单手 | ≤ 2 秒上限 | 最慢 2.1 秒 |
| 棋圣（8 层）单手 | ≤ 5 秒上限 | 最慢 5.06 秒 |
| 棋神（12 层）单手 | ≤ 12 秒上限 | 最慢 12.02 秒 |
| evaluate 叶子 | ~40-60µs | 20 子局面 |
| 全量重绘 | < 5ms | 含木纹纹理 |
| 在线广播端到端 | < 50ms（局域网） | 落子到对端重绘 |

时间上限的语义：**超时回退到上一层完整结果**，绝不采纳半截搜索——
棋神档最慢 12 秒正是上限精确生效的证据。

## 6. 已知边界与刻意取舍

1. **同浏览器多标签**共享 localStorage：对局记录/live 存档互相覆盖（后写者胜），
   在线会话由 tabKey 指纹防止抢占，但两个标签页同时下**不同**的本地棋局时，
   自动续上只保留最后写入者的局面。真实场景（不同设备、单标签页）不受影响。
2. **服务器内存态**：房间不落盘，重启即失（客户端自动感知并提示重新加入）。
   需要持久化在线房间时，应把 rooms 序列化到文件/数据库并在启动时恢复。
3. **评估无先手权项**：叶子评估不区分轮到谁，靠搜索深度弥补；
   极端局面下（双方棋型分差极大但先手在弱方）可能选保守着法。
4. **窗口法评估的盲区**：跨窗口长程组合（隔两格以上呼应）不敏感；
   由候选邻域与搜索深度部分弥补。
5. **平局构造困难**：满盘无五连的测试局面难以人工构造，平局路径靠代码审查
   与在线满盘逻辑复用保证（`moves.length >= SIZE*SIZE`）。
6. **file:// 与在线模式**：单机模式双击即玩；在线模式经 `file://` 打开时
   回退连接 `http://127.0.0.1:3000`，跨机器使用请通过服务器地址访问页面（同源最稳）。
7. **AI 思考阻塞主线程**：计算是同步的（最长 12 秒），期间页面不响应点击
   （守卫已拦截），但浏览器标签页可能显示"无响应"警告——若未来需要消除，
   应把搜索移入 Web Worker（引擎已是纯逻辑，迁移成本低）。

## 7. 回归检查清单（改版后必跑）

```bash
node test-engine.mjs        # 引擎：胜负/棋型/战术/性能
node --check gomoku-server.js
node -e "…提取<script>… node --check"   # 页面脚本语法
```

浏览器手检五分钟流程：人机下一局（含悔棋/提示）→ 切双人下一局 → 切在线双标签
匹配下一局 → 开第三标签观战 → 刷新页面确认续上 → 记录回放一局。
