# 08 · 部署指南

本指南覆盖从"自己电脑上和朋友玩"到"云服务器公开对战"的全部部署方式。
服务器是零依赖的 Node 程序（仅内置模块），任何能跑 Node ≥16 的环境都能部署。

## 1. 一键启动（Windows / macOS / Linux 桌面）

| 平台 | 启动方式 | 行为 |
|------|----------|------|
| Windows | 双击 `start-gomoku.bat`（可带端口参数：`start-gomoku.bat 3000-3010`） | 启动服务器 + 自动打开浏览器；关闭窗口即停止服务器 |
| macOS / Linux | `./start-gomoku.sh`（或 `./start-gomoku.sh 3000-3010`） | 同上 |

启动器会先检查 Node.js 是否安装（未安装给出官网提示），然后运行服务器；
服务器启动后**自动打开默认浏览器**直达游戏页面——这就是"打开即玩"的实现方式
（浏览器沙箱不允许网页启动进程，所以入口是启动器而不是 index.html；
index.html 双击打开仍然可以玩人机/双人模式）。

> **为什么启动器脚本是英文的**：cmd 解析 `.bat` 用的是系统 ANSI 代码页
> （中文 Windows 为 GBK），UTF-8 编码的中文会被拆成乱码字节，
> 轻则回显乱码、重则把乱码当命令/吞掉括号直接报语法错误（`chcp 65001` 也救不了解析阶段）。
> 因此 `start-gomoku.bat` 刻意保持纯 ASCII，所有中文提示由 Node 进程输出——
> Node 在 Windows 走宽字符控制台 API（WriteConsoleW），中文不会乱码。
> Linux/macOS 的 `start-gomoku.sh` 无此问题（bash 原生 UTF-8），保留了中文提示。

## 1.5 Docker 一键部署（推荐）

装好 Docker 后，**一个脚本完成构建 + 启动 + 健康检查 + 打开浏览器**：

| 平台 | 一键部署 |
|------|----------|
| Windows | 双击 `docker-deploy.bat`（可带端口：`docker-deploy.bat 8080`） |
| Linux / macOS | `./docker-deploy.sh 3000` |
| 停止 | `stop-gomoku.bat 3000` / `./stop-gomoku.sh 3000`（Docker 容器与端口进程一并清理） |

脚本内置：Docker 存在性检查 → 镜像构建（失败自动换国内镜像源 daocloud/1ms 重试）→
重建同名容器（`-p 端口:3000 --restart unless-stopped`）→ HTTP 健康检查 → 自动打开浏览器。
自定义配置：编辑本机 `config.json` 后 `docker restart gomoku`（compose 用户用挂载即可）。
文件名要求全 ASCII：cmd 对中文文件名的批处理同样存在编码风险。
## 1.8 停止脚本

`stop-gomoku.bat [端口]` / `stop-gomoku.sh [端口]`（默认 3000），一个脚本覆盖两种运行方式：

1. 移除 Docker 容器 `gomoku`（如以 Docker 方式运行）；
2. 兜底结束仍监听端口的进程——Linux 链路为 `ss` 取 PID → `fuser` → `lsof` →
   按进程名 `pkill -f gomoku-server`（Ubuntu 预装 ss 与 pkill，开箱即用）；
   Windows 链路为 `netstat -ano` 定位 PID 后 `taskkill`。

脚本可重复执行（幂等）；停止后用对应 deploy/start 脚本重新启动。
## 2. 端口配置（含端口范围）

优先级：**命令行参数 > `PORT` 环境变量 > `PORT_RANGE` 环境变量 > 默认 3000**。

```bash
node gomoku-server.js 3000            # 单端口
node gomoku-server.js 3000-3010       # 范围：3000 被占用自动顺延到 3001、3002...
node gomoku-server.js 3000,8080       # 候选列表
PORT_RANGE=3000-3010 node gomoku-server.js
HOST=127.0.0.1 node gomoku-server.js  # 只监听本机（默认 0.0.0.0 监听全部网卡）
```

- 范围最多展开 100 个端口；全部不可用时打印提示并自动打开
  `http://127.0.0.1:首选项/`（若服务器其实已在运行，直接可用）。
- Linux 下使用 1024 以下端口需要 root（建议直接用高位端口或反向代理）。
- 启动日志会打印**实际绑定的端口**与所有局域网/公网网卡地址，照着告诉朋友即可。

## 2.5 配置文件（config.json，git pull 不覆盖）

服务器启动时按顺序查找配置：**本机 `config.json` → 仓库模板 `config.example.json` → 内置默认值**。
首次启动若本机没有 `config.json`，会自动从模板复制一份并提示。
`config.json` 已列入 `.gitignore`：提交到 git 后再 `git pull`，**你的本地配置不会被覆盖**；
模板字段有变化时拉取的是 `config.example.json`，新字段按内置默认值生效，互不干扰。

```json
{
  "port": 3000,            // 端口或范围："3000-3010"（被占自动顺延）/ "3000,8080"
  "host": "0.0.0.0",       // 0.0.0.0=所有网卡（局域网/云）；127.0.0.1=仅本机
  "noOpen": false,         // true=不自动打开浏览器（云服务器/容器建议 true）
  "specMax": 5000,         // 每房间观战人数上限
  "roomTtlHours": 2,       // 房间闲置回收时间（小时）
  "reconnectGraceMs": 8000,// 断线保留座位宽限（毫秒）
  "passwordMaxLen": 16     // 房间密码最大长度（区分大小写）
}
```

**优先级**：命令行参数（如 `node gomoku-server.js 3000`）> 环境变量（`PORT` / `HOST` /
`GOMOKU_NO_OPEN`）> `config.json` > 内置默认值。页面客户端也会读取 `config.json`
（服务器地址 + `/config.json` 接口），`file://` 打开页面时按配置端口回退连接。
## 3. Docker 部署

仓库自带 `Dockerfile` 与 `docker-compose.yml`（容器内自动设置 `GOMOKU_NO_OPEN=1`
禁用浏览器弹窗）。

> **国内网络拉取基础镜像**：Docker Hub 直连可能超时，可先从镜像源拉取再打标签：
> ```bash
> docker pull docker.m.daocloud.io/library/node:20-alpine
> docker tag docker.m.daocloud.io/library/node:20-alpine node:20-alpine
> ```
> 或在 Docker Desktop 设置中配置 registry-mirrors。

```bash
# 方式一：docker 命令
docker build -t gomoku .
docker run -d --name gomoku -p 3000:3000 --restart unless-stopped gomoku

# 方式二：docker compose
docker compose up -d

# 自定义端口（映射到宿主机 8080）
docker run -d -p 8080:3000 --restart unless-stopped gomoku
```

镜像基于 `node:20-alpine`，复制 `index.html`、`gomoku-server.js` 与 `config.example.json`（容器首启自动生成 config.json）。自定义配置：在 compose 里挂载 `- ./config.json:/app/config.json`（可改端口/观战上限等，容器重建不丢）。实测：容器 + 双浏览器标签匹配对局、双端落子同步、`docker restart` 后客户端自动感知会话失效并提示重新加入。
升级版本：重新 build + up 即可（房间是内存态，重启会清空，客户端会自动提示重新加入）。

> 注：Dockerfile/compose 已按标准写法提供，若你的环境无 Docker，可直接用 §2/§4 的方式运行。

## 4. 云服务器部署（公网对战）

### 4.1 直接运行 + systemd（推荐）

```bash
# 1) 安装 Node（以 Ubuntu 为例）
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs

# 2) 上传项目（至少 index.html 与 gomoku-server.js），例如放到 /opt/gomoku
scp index.html gomoku-server.js user@your-server:/opt/gomoku/

# 3) systemd 常驻
sudo tee /etc/systemd/system/gomoku.service >/dev/null <<'EOF'
[Unit]
Description=Gomoku Online Server
After=network.target
[Service]
WorkingDirectory=/opt/gomoku
ExecStart=/usr/bin/node gomoku-server.js 3000
Environment=GOMOKU_NO_OPEN=1
Restart=always
RestartSec=3
[Install]
WantedBy=multi-user.target
EOF
sudo systemctl enable --now gomoku

# 4) 云控制台开放安全组/防火墙 TCP 3000
```

之后玩家访问 `http://<公网IP>:3000`。pm2 方式：`pm2 start gomoku-server.js --name gomoku`。

### 4.2 Nginx 反向代理（80/443 入口）

```nginx
server {
    listen 80;
    server_name your.domain.com;
    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_buffering off;            # 关键：SSE 必须关闭缓冲
        proxy_read_timeout 3600s;       # 长连接保活
    }
}
```

- **SSE 必须关闭代理缓冲**（`proxy_buffering off`），否则事件会被攒住不下发。
- HTTPS：用 certbot 给域名签证书，浏览器地址为 https 时自动同源连接，无需改代码。
- 客户端逻辑与部署方式无关：页面从服务器地址打开即同源连接；
  房间、密码、观战全部照常。

### 4.3 安全清单（公网暴露时）

- 房间密码可阻止陌生人加入特定对局（明文口令级别，防误入不防攻击）。
- 建议置于 Nginx 之后并限制速率（`limit_req`）；服务器自身无持久化数据，泄漏面小。
- `HOST` 环境变量可改为 `127.0.0.1` 只对本机提供服务（配合反代）。

## 5. 常见问题

| 现象 | 原因与处理 |
|------|-----------|
| 页面提示"未检测到对战服务器" | 服务器没启动或端口不对：用启动器启动，或检查端口/地址 |
| 启动日志"端口不可用，尝试下一个" | 按范围配置顺延；不想要此行为就指定单一端口 |
| 云服务器上访问不了 | 安全组/防火墙未放行该 TCP 端口 |
| 经 Nginx 代理后落子没有实时推送 | `proxy_buffering off` 未配置 |
| 服务器重启后房间消失 | 房间为内存态（TTL 2 小时）；重新输入房间号即可，客户端会提示 |
